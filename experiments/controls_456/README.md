# REPRISE controls ④–⑥

実験仕様は `protocol.json`, 実行入口は `launch.sh` です. hades用の既存データとチェックポイントの絶対パスを `src/data.py` と `src/vendor/vins/config.py` に記載しています. パスを移植する場合は変更してください. パスワードや認証情報は含みません.

ユーザーがCUB-200-2011とCIFAR-100の結果を手法設計で参照していないと確認したため, この2設定を新しい評価として固定します. 学習済み特徴モデルの事前学習で未見だったとは主張しません. CUBのImageNetとの重複に関する注意は公式サイトを参照してください.

## 実行

```bash

```

既存R5がGPUを使う工程を終え, 各GPUが空いた時に処理を開始します. 他の実験を停止しません. プロセスはSSH切断後も継続します. CPUは通常各処理2スレッド, 画像重複検査は4ワーカー, nice 10です.

## 実験と記録

- ④ 576条件. NINCOとSSB-hardから4クラスずつ, 各8評価画像, 共通ID128画像. 2つの固定履歴を使い, r=0,1,2,5,10,20, 履歴バッチ1,16,256, 元のLP15回と収束LPを比較. 評価は状態を復元して毎回独立に行います. 同一バッチの類似画像は, 別の予約画像で比較します. 4クラスずつの診断であり, 広いクラス母集団への確定的結論にはしません.
- ⑤ 592条件. 4パネル, 各2未知クラス. OOD割合0,0.1,1,5,20%, 再来1,5,20回, random/burst/long_gap, 保持上限1000/5000/20000/無制限. 最大40000画像. 同じ画像を1ストリーム内で繰り返しません. 0%では誤警報を報告します. 再来1回のlong_gapは「再来未定義」と明記します.
- ⑤ 計算量の追加24条件. panel0の20回条件で全割合のrandom, 0.1%のlong_gap, 0%をそれぞれ4容量で測定. 生画像から特徴抽出,TINS,近傍探索,グラフ更新まで測ります. それ以外のキャッシュ利用時間をend-to-endとは呼びません.
- ⑥ 18条件. CUB100/100, CIFAR50/50, B14画像特徴のみ/CLIP画像特徴のみ/元のB14+L14, 順序3seed. 単独特徴の候補選択も画像プロトタイプで行います. 主比較はs0=1. TINSとその積は別名で併記します. 同じ特徴のkNNとMahalanobis++の設定は旧dev1だけで固定します.

計1210条件. 全画像スコア, 行番号, 履歴, 同点件数, 実現ID TPR, メモリ上限検証, 処理時間内訳を保存します. 閾値は旧dev1のIDスコアから決めて固定します. 新しいtest結果からの方式選択は行いません.

`data/*/images.parquet` と `manifest_frozen.json` は分割記録, `plans/` は履歴とタスク一覧, `results/` は条件別スコア/集計, `reports/` は自動更新の表と曲線です. `status/`, `logs/`, `failures/` で進捗と個別の失敗を確認できます. 依存処理に失敗した条件も個別に記録します.

## 検証と制約

`src/test_controls.py` は元の凍結実装との一致, 状態復元, 全保持集合の上限と正確な近傍, 収束LPのバッチ整合, 未来画像の非参照, 単独特徴条件のテキスト候補からの独立を検証します. GPUが空いた後の旧dev校正でTINSのオンライン状態管理と元実装の一致を追加検証し, 不一致なら停止します.

FPR95はIDの95%以上を受理する実測閾値で計算し, 同点を全受理します. 旧集計の「TPRが95%に最も近いROC点」とは小差がありえます. 今回の比較は全条件で同じ定義です.

長期ストリームの全処理時間には各バッチの画像読み込みと抽出を含みますが, 固定支持画像の事前抽出は含みません. モデルロード/状態初期化は別記します. 遅延はバッチ準備完了からの処理時間で, 仮想到着キューの待ち時間は含みません. CPUはプロセス最大RSS, GPUはPyTorch最大allocated/reservedです.

OpenOODの④⑤は既に利用済みtestを用いた機構診断です. ⑥の未使用確認と区別してください. 重複排除は復号後RGB完全一致であり, リサイズや別圧縮の近似重複まで保証しません.
